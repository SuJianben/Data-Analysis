# 2026-09-11 数据页面导航性能优化

## 本次目标

- 缩短侧栏 Tab 切换等待时间，并让稍慢的跳转具有即时、明确的加载反馈。

## 修改范围

- 新增统一 Cloudflare 读取模块 `src/services/connectors/cloudflare-request.ts`。
- 修改报表与用户事件连接器，统一使用短缓存读取策略。
- 调整概览、菜单分析、全局埋点、用户行为及用户详情页面的动态渲染配置。
- 新增全局路由加载骨架，调整侧栏导航等待状态与响应式样式。
- 调整 Cloudflare Worker 的全局点击报表聚合查询。

## 新增内容

- 可复用的 Cloudflare 服务端读取模块，统一处理认证、超时、JSON 校验、错误信息与缓存策略。
- 路由级加载骨架，在新页面数据返回前提供即时反馈。
- 本次性能问题的独立 BUG 日志。

## 调整内容

- 常规报表请求增加 30 秒短缓存，降低同一时间范围反复切换时的 Worker / D1 查询次数。
- 数据健康读取保留 `no-store`，避免健康状态因缓存失去实时性。
- 移除主要报表页面的 `force-dynamic`，避免覆盖请求自身的缓存策略。
- 全局点击记录按设备、页面、元素、区域、目标等实际表格维度聚合，日期趋势继续由独立趋势接口提供。

## 影响范围

- 影响数据读取性能与页面切换反馈，不改变日期筛选、统计口径、表格筛选、分页或图表结构。
- 新数据写入后，常规报表最多可能在 30 秒内仍显示缓存结果；数据健康页面不受该延迟影响。

## 自检结果

- `npm run typecheck` 通过。
- `npm run build` 通过，17 个页面与接口路由正常生成。
- Worker `npm run typecheck` 通过并成功发布。
- Vercel 生产构建成功并发布至 `https://tkf-signal.vercel.app`。
- 真实浏览器验证概览、菜单分析、全局埋点、用户行为连续切换成功，加载骨架在 150ms 内出现。
- 修复后 RSC 请求约为：全局埋点 396ms、用户行为 358ms、菜单分析 356ms；控制台无错误或警告。

## 遗留问题

- 全局埋点当前仍将所选范围的完整列表发送给前端，由前端完成筛选和分页。当前跳转已明显改善；若数据规模继续增长，可再升级为 Worker 端分页与独立聚合接口。
