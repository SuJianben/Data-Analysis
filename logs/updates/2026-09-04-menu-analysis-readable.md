# 2026年09月04日更新日志：菜单分析可读化

## 本次目标

让菜单分析页面和全局点击页面保持一致，减少 `(not set)`、`L0`、`label/link` 等原始字段带来的阅读干扰。

## 修改范围

- `src/components/menus/menu-presenters.ts`
- `src/components/menus/menu-table.tsx`

## 调整内容

- 新增菜单展示转换模块，统一处理菜单名称、层级、行为、触发方式和设备名称。
- 展示层将 `(not set)` 和空值归并为“未命名菜单”或“未标注”，不删除数据库中的原始记录。
- 按“菜单 key（或菜单名称）+ 设备”合并重复展示行，点击次数按真实记录相加。
- 同一菜单的多个真实行为会合并显示，例如“跳转 / 展开 / 收起”。
- `navigate`、`expand`、`collapse`、`label`、`link`、`indicator` 和设备类型改为中文可读名称。
- 原始菜单 key 仍保留在菜单单元格的悬停提示中，便于追溯。

## 自检

- `npm run typecheck` 通过。
- `npm run build` 通过。
- 本机 `/menus` 返回 200。
- 页面已确认出现“主菜单”“跳转”“桌面端”等易读字段，旧的 `L0` 格式不再直接展示。
- 未删除或篡改数据库中的真实菜单统计数据。

## 遗留问题

- `(not set)` 本身是 GA4 返回的真实不完整字段，当前只在展示层归并；如需彻底减少该字段，需要后续检查 Shopify 菜单事件的参数来源。
