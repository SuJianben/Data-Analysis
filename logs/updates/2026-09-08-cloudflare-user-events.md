# 2026-09-08 Cloudflare 用户行为数据链路

## 本次目标

把用户级点击数据从临时运行环境迁移到 Cloudflare Worker + D1，并实现匿名访客与登录客户的稳定区分。

## 修改范围

- Cloudflare Worker 用户事件接口与 D1 数据库结构。
- Next.js 用户事件接收、远程读取和用户页面。
- Shopify 正在使用主题的全局点击脚本与身份传输模块。
- Vercel 生产环境的 Worker 地址与服务端密钥配置。

## 新增内容

- 新增独立的 `cloudflare/user-events` 子项目，提供健康检查、事件写入、用户摘要和用户详情接口。
- 新增用户身份、事件校验、事件写入、远程读取等独立模块。
- 新增隐私许可感知的浏览器身份脚本，仅保存匿名访客 ID、会话 ID 和不可逆客户哈希。
- D1 新增用户事件表、唯一去重约束和查询索引。

## 调整内容

- 用户页面改为同时支持匿名访客和登录客户。
- 登录客户按客户哈希跨浏览器汇总；共享浏览器出现多个客户时，不强行归属匿名行为。
- Shopify 全局点击监听切换到捕获阶段，避免第三方菜单组件阻止事件后造成漏记。
- Vercel 兼容接收接口增加来源与服务端密钥校验，并把数据转发到 D1。

## 影响范围

- 正式店铺后续产生的已获统计许可点击会进入 D1。
- GA4 原有汇总数据与埋点发送逻辑保持不变。
- 不采集表单自由文本、姓名、邮箱、电话和 Shopify 原始客户 ID。

## 自检结果

- Worker 本地 D1：写入、去重、跨浏览器归属、非法来源拒绝、未授权读取拒绝均通过。
- Cloudflare 线上：健康检查、D1 迁移、写入和密钥读取通过。
- Shopify 真实链路：页面加载、隐私许可、菜单点击、Worker 写入、D1 查询、Vercel 用户摘要和详情读取全部通过。
- 自检产生的部署测试和浏览器测试数据已按事件来源及访客标识删除，数据库未保留人工数据。

## 遗留问题

- 用户行为页面和同名 Next.js 读取接口目前沿用现有站点访问方式；如需限制为团队成员查看，应单独增加面板登录保护。
- GA4 自动同步仍是独立链路，本次没有迁移到 Worker。
