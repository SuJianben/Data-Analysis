# 2026-09-20 Vercel Blob 暂停导致线上数据停更

## 缺陷现象

- 本机队列持续回收事件，SQLite 和 GA4 同步都有新增数据，但线上面板停留在 2026-09-18 上午。
- `/api/health` 返回 HTTP 500，线上用户行为看不到本地已经存在的购买记录。
- 两个 Windows 同步任务均因发布阶段失败而返回非零结果。

## 根因

- 自动化曾在每次 5 分钟事件回收出现新增数据时覆盖上传整份 SQLite 快照。
- Vercel Blob 存储被暂停，`head`、下载和上传都会抛出 `This store has been suspended`。
- 运行时没有吞掉快照源异常，导致健康接口和部分页面请求直接失败。

## 影响范围

- 本地主库数据没有丢失，但线上只读副本无法更新。
- 2026-09-18 至 2026-09-19 本地已有 TMS 3 条、FKK 2 条、DTK 1 条购买，线上旧快照不可见。
- AI 分析结果的线上持久化同样依赖 Blob，也会受暂停影响。

## 修复

- 改用 Cloudflare KV 中转 gzip 压缩后的 SQLite 只读快照，本地 SQLite 仍是唯一主库。
- 普通事件仅在每小时完整同步时合并发布，购买事件在最近一次 5 分钟任务中优先发布。
- Vercel 运行时通过 Worker `HEAD/GET` 检查版本，完成 SHA-256 和 SQLite 完整性校验后再原子切换。
- 远程快照异常时继续使用最后有效数据库，不再让页面直接返回 500。
- AI 分析 JSON 同步迁移到相同 KV，并保留本地 SQLite 兜底。

## 验证状态

- KV 命名空间已创建，Worker 快照上传、HEAD、下载、哈希和 SQLite 完整性验证通过。
- 当前远程快照包含 33,232 条用户事件，压缩后约 5.77 MiB。
- 远程快照中已核对 TMS 3 条、FKK 2 条、DTK 1 条近期购买。
- AI 分析远程写入、读取和测试数据清理通过。
- Windows 事件同步和完整同步任务最近执行结果均恢复为 0。
- Vercel 应用仍需发布新读取代码并完成线上页面验收。
