# BUG：数据页面 Tab 跳转反馈迟缓

## 日期

2026-09-11

## 复现条件

在 Vercel 正式站通过左侧导航切换概览、菜单分析、全局埋点或用户行为页面。页面使用指定时间范围时，点击后旧页面会短暂停留，用户容易误以为没有触发跳转。

## 影响范围

- 概览、菜单分析、全局埋点、用户行为及用户详情页面。
- 全局埋点页面返回数据较多，延迟感受最明显。

## 根本原因

- 数据页面使用 `force-dynamic`，导致每次访问都在 Vercel 重新渲染。
- Cloudflare Worker / D1 的报表读取统一使用 `no-store`，同一时间范围的重复请求无法复用结果。
- 全局点击列表按日期参与分组，表格并不展示日期，却可能重复返回同一元素在不同日期的记录。
- 页面没有路由级加载状态，导航完成前仍显示旧页面，缺少即时反馈。

## 本次处理

- 数据报表读取改为 30 秒短缓存；数据健康接口继续实时读取。
- 移除主要数据页面会覆盖请求缓存策略的强制动态配置。
- 新增路由级加载骨架，并为导航保留等待状态提示。
- 全局点击列表改为在所选时间范围内聚合相同维度的记录，不再按日期拆行。

## 状态

已修复并发布。

## 验证

- Next.js 类型检查与生产构建通过。
- Cloudflare Worker 类型检查与发布通过，版本 `bca8a928-f0e0-441a-a87e-c0cc1e95cd35`。
- Vercel 生产发布成功，正式域名仍为 `https://tkf-signal.vercel.app`。
- 真实浏览器切换时，150ms 内可见加载骨架。
- 同类 RSC 请求实测：全局埋点约从 1142ms 降至 396ms，用户行为约从 660ms 降至 358ms；页面控制台无报错。
