# BUG：腾讯云部署目录与 GitHub 版本漂移

## 日期

2026-09-08

## 复现条件

将 GitHub 提交 `d22688a` 中的“删除数据源页面”变更部署到腾讯云 `/opt/tkf-signal` 时，先执行补丁试应用。多个文件出现上下文不匹配，且该服务器目录不是 Git 仓库，无法通过提交历史判断线上版本。

## 影响范围

- 无法安全使用 `git pull` 或整份 GitHub 提交补丁完成部署。
- 如果直接覆盖文件，可能丢失腾讯云上已有但未进入 GitHub 的改动。
- 首轮精简修改后，公网首页仍显示“同步数据”和“管理数据源”两处旧入口，造成线上界面与预期不一致。

## 根本原因

- `/opt/tkf-signal` 是非 Git 部署目录，缺少可追溯的提交和分支信息。
- 腾讯云源码与 GitHub `main` 分支已经存在版本差异，同一功能的部分文件已更新，部分文件仍保留旧实现。
- 部署时如果只依赖本地差异或单次文本搜索，不能完整识别服务器实际残留。

## 本次处理

- 先通过补丁试应用确认基线不匹配，在未改动文件前自动停止。
- 读取服务器实际导航、页面、进程和 Nginx 配置，根据实际代码精确移除数据源入口与页面。
- 修改前对目标文件生成压缩备份。
- 校验 `.next` 的绝对路径后删除可再生的构建产物，执行全新生产构建并重启 `tkf-signal` 服务。

## 状态

本次“数据源页面下线不完整”已修复并验证。

部署目录缺少 Git 基线的结构性问题仍未解决，后续应将服务器改为从 GitHub 固定提交或构建产物发布，并将环境变量、数据库与可部署代码分离。

## 验证

- Next.js 16.3.4 生产构建和 TypeScript 检查通过。
- 构建路由清单中不再包含 `/sources`。
- 公网直接访问 `/sources` 返回 404。
- 公网首页和主导航已无“数据源”、“同步数据”、“管理数据源”及 `/sources` 链接。
- `/api/health` 返回正常，数据库仍包含 66 条菜单数据、63 条指标数据和 15 个快照。
