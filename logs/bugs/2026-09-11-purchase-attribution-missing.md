# 2026-09-11 购买事件未归入用户行为

## 缺陷

- 概览从 GA4 汇总数据中显示 2026-09-10 有 1 次购买。
- Cloudflare D1 的 `user_events` 同期只有 `global_click`，没有 `purchase`。
- 用户行为列表因此能显示匿名点击轨迹，但所有用户的购买数均为 0，无法判断购买属于哪条用户轨迹。

## 根因

现有 Shopify 自定义 Pixel 已将 `checkout_completed` 发送给 GA4，但没有同时发送给 TKF Signal 用户事件 Worker。GA4 汇总表和用户级事件表是两条独立数据链，前者知道购买总数，后者没有购买事件可供归因。

## 修复

- 新增 Shopify Pixel 购买桥接，订阅 `checkout_completed` 并写入 `eventName: purchase`。
- 优先复用主题写入顶层存储的匿名访客和会话标识，使购买与购买前点击处于同一访客链路。
- 登录/结账客户只保存 SHA-256 哈希；订单同样只保存哈希，不发送原始客户 ID、订单 ID或其他个人信息。
- Worker 现有身份归并逻辑会把同一浏览器且仅关联一个客户哈希的购买前匿名行为归入该客户；共享浏览器出现多个客户时仍保持匿名，避免串号。

## 影响范围

- 修复只影响启用后的新购买事件，历史上没有写入 `user_events` 的购买无法从 GA4 汇总数据反推出具体用户。
- Shopify Pixel 正式保存后生效。

## 验证

- Pixel 脚本通过 `node --check` 语法检查。
- 使用模拟 `checkout_completed` 事件完成传输测试：访客标识匹配、客户/订单哈希均为 64 位、商品数量与设备映射正确，序列化载荷不含原始客户或订单 ID。
- Shopify 后台已正式保存 Pixel，并出现“像素已保存”提示。
- 保存后重新读取 Pixel 全文共 8,648 个字符，与待保存版本完全一致；Worker 接口和 `orderIdHash` 字段均存在。

## 状态

2026-09-11 的 Pixel 发送逻辑已上线，但当时的验证只覆盖了模拟代码执行，没有覆盖 Shopify 沙箱发出的真实跨域请求，因此“已修复”的结论不完整。

2026-09-14 复查发现，Shopify 自定义 Pixel 运行在不透明来源沙箱中，请求携带 `Origin: null`；Worker 原先只允许店铺域名，导致购买事件被 403 拒绝。GA4 使用独立的数据通道，所以仍能看到购买汇总，而 D1 用户行为链没有购买记录。

现已在 Worker 增加受限的 Shopify 沙箱购买入口：仅接受站点与来源匹配、事件类型为 `purchase`、目标为 `checkout_completed`、订单哈希及交易字段格式正确且发生时间有效的单条事件。普通不透明来源请求仍被拒绝。

线上正向测试确认合法事件写入 D1，反向测试确认普通点击返回 403；测试记录已精确删除并复查为 0。Worker 版本 `db4f3815-7d63-475d-9ff5-762d0c54b5cc` 已发布。历史未进入 D1 的购买无法反推具体用户，下一笔真实订单将用于最终业务验收。
