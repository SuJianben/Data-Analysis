# BUG：生产构建时 SQLite 初始化锁冲突

## 日期

2026-09-02

## 复现条件

Next.js 生产构建并行收集多个动态页面数据，各工作进程同时初始化数据库并切换日志模式。

## 影响范围

首次 `npm run build` 在页面数据收集阶段报 `database is locked`，开发代码类型检查不受影响。

## 根本原因

实验性 `node:sqlite` 驱动在多个构建进程中同时执行初始化 PRAGMA 和建表语句，对同一数据库文件产生锁竞争。

## 修复

- 使用稳定的 `better-sqlite3` 驱动
- 设置 `busy_timeout`
- 将数据库原生模块配置为 Next.js 服务端外部依赖
- 保留单进程连接复用与数据库唯一约束

## 状态

已修复。

## 验证

重新执行类型检查和生产构建，全部通过且不再出现数据库锁或实验性 API 警告。
