# 2026-09-17 D1 配额耗尽导致页面崩溃

## 缺陷

- Cloudflare D1 免费读取额度耗尽后，概览、菜单、全局点击、用户行为和数据健康页面的服务端数据请求直接抛出异常。
- 页面进入 Next.js 未处理错误状态，显示 `This page couldn't load`，用户无法继续浏览面板。

## 复现与影响

- 生产日志确认 `/users` 报错为 `D1_ERROR: Your account has exceeded D1's free tier daily row read limit`。
- `/menus`、`/global-clicks`、`/health` 同时出现 HTTP 500 或非 JSON 响应错误。
- 错误编号 `2676442625` 与用户截图一致。

## 根因

- Cloudflare 请求层没有区分可恢复的数据源故障与代码异常。
- Server Component 未处理 D1 配额、Cloudflare 5xx、超时或网络中断，异常直接中止整页渲染。
- 用户行为原始数据没有本地副本，不能用空数组伪装为“0 条数据”。
- 首次补入本地快照后，Vercel `/tmp` 仍可能复用上一部署的旧数据库文件，导致不同实例出现数据不一致。
- Cloudflare Worker 将 D1 免费额度错误包装为 HTTP 400；旧降级规则仅识别 429/5xx，部分站点未进入本地兜底。

## 修复

- 增加可重试 Cloudflare 读取错误类型，统一识别配额、5xx、429、超时和网络故障。
- GA 报表在 Cloudflare 暂时不可用时自动读取部署内的本地 SQLite 快照。
- 通过 D1 导出通道恢复 23,345 条用户行为到本地快照；用户行为页在 D1 不可用时继续展示数据。
- Vercel 临时数据库按部署快照 SHA-256 指纹隔离，杜绝新部署继续读取旧 `/tmp` 文件。
- 按明确的 D1 日读取/写入额度错误内容识别可恢复的 HTTP 400，不把普通参数错误误判为临时故障。
- 数据健康页增加本地同口径计算，D1 不可用时仍检查同步新鲜度、连续性、字段质量、购买轨迹和数据量波动。
- 数据健康没有等价的本地计算结果时显示正式的数据源不可用状态，不再整页崩溃或误报 0 条。
- 增加应用级错误边界，覆盖其他未预期的服务端渲染错误。
